# BE-102: Provider catalog, studios, services and portfolios

Status: In Review
Owner: Khai
Reviewers: Khoi Nguyen; Ly for DB interaction; Khoa for wire shapes
Jira: None
Branch: `feature/BE-102-provider-catalog`

## Goal and scope

Implement the provider discovery and catalog endpoints on top of the BE-101 foundation.
Target date 2026-11-13 to 2026-11-15 (see the
[work plan](../../docs/backend/mvp-rebuild-work-plan.md)).

In scope, split into five slices on `feature/BE-102-provider-catalog`:

1. **Slice 102a (P0 - Public discovery):** `GET /v1/explore`, `GET /v1/photographers`,
   `GET /v1/photographers/:id`, `GET /v1/studios`, `GET /v1/studios/:id`, `GET /v1/tags`.
2. **Slice 102b (P0 - Studios & team):** `GET /v1/me/studios`, `POST /v1/studios`,
   `PATCH /v1/studios/:id`, `GET /v1/studios/:id/team`.
3. **Slice 102c (P0 - Services):** `GET /v1/me/services`, `POST /v1/services`,
   `POST /v1/studios/:id/services`, `PATCH /v1/services/:id`, `DELETE /v1/services/:id`.
4. **Slice 102d (P0 - Portfolios & images):** `GET /v1/me/portfolios`, `GET /v1/portfolios`,
   `GET /v1/portfolios/:id`, `POST /v1/portfolios`, `POST /v1/studios/:id/portfolios`,
   `PATCH /v1/portfolios/:id`, `DELETE /v1/portfolios/:id`, `POST /v1/portfolios/:id/images`,
   `PATCH /v1/portfolio-images/:id/tags`.
5. **Slice 102e (P1 - Invitations, members, resources & add-ons):**
   `GET /v1/me/invitations`, `POST /v1/studios/:id/invitations`, `PATCH /v1/invitations/:id`,
   `PATCH /v1/studios/:id/members/:userId`, `DELETE /v1/studios/:id/members/:userId`,
   `GET /v1/studios/:id/resources`, `POST /v1/studios/:id/resources`,
   `PATCH /v1/resources/:id`, `DELETE /v1/resources/:id`,
   `GET /v1/services/:id/add-ons`, `POST /v1/services/:id/add-ons`.

Out of scope: `POST /v1/portfolio-images/:id/index` (owned by BE-104),
`GET /v1/studios/:id/dashboard` (allocated to P2 / BE-108), uploads and projects (BE-103),
bookings (BE-105).

## Dependencies and open decisions

- Builds on BE-101 (`defineRoute`, `PgDatabase`/`Transaction`, `authenticateVerified`,
  `ApiError`). Stacked on `feature/BE-101-api-contract-auth` and retargeted to `dev` once
  BE-101 merges.
- Catalog request validators reuse the existing `@frameroom/shared` inputs. API-specific
  query/response projections remain in `apps/api/src/schemas/catalog.ts`; Khoa reviews
  their eventual shared export and frontend compatibility.
- DB-102 migrations and `public.providers` view from Ly are required before Cloud verification.
- Manager authorization is checked against `studio_members` (`role = 'manager'` and
  `studios.deleted_at IS NULL`) inside the request transaction.

## Acceptance criteria

- [x] Static `/v1/photographers/me` is registered before `/v1/photographers/:id` and both are tested.
- [x] Public reads exclude hidden/deleted providers, draft portfolios, hidden images and inactive services.
- [x] `GET /v1/explore` supports `genre`, `city`, `district`, `priceMax`, `page` and `pageSize <= 50`.
- [x] Studio creation atomically inserts the studio and its first `manager` in `studio_members`.
- [x] Services and portfolios enforce a single owner (personal photographer or studio) and soft deletion.
- [x] Invitations and membership changes protect the last studio manager and active booking assignments.
- [x] Full local `pnpm check` passes: 11 test files, 141 tests after the review corrections.
- [ ] Cloud database/RLS/Storage and real PostgreSQL concurrency verified (deferred by user).
- [ ] Frontend/shared compatibility accepted and independent reviewer approval obtained.
