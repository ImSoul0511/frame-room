# BE-102: Provider catalog, studios, services and portfolios

Status: In Progress
Owner: Khai
Reviewers: Khoi Nguyen; Ly for DB interaction; Khoa for wire shapes
Jira: None
Branch: `feature/BE-102-provider-catalog`

## Goal and scope

Implement the provider discovery and catalog endpoints on top of the BE-101 foundation[cite: 22].
Target date 2026-11-13 to 2026-11-15 (see the
[work plan](../../docs/backend/mvp-rebuild-work-plan.md))[cite: 22].

In scope, split into five slices on `feature/BE-102-provider-catalog`[cite: 22]:

1. **Slice 102a (P0 - Public discovery):** `GET /v1/explore`, `GET /v1/photographers`,
   `GET /v1/photographers/:id`, `GET /v1/studios`, `GET /v1/studios/:id`, `GET /v1/tags`[cite: 22].
2. **Slice 102b (P0 - Studios & team):** `GET /v1/me/studios`, `POST /v1/studios`,
   `PATCH /v1/studios/:id`, `GET /v1/studios/:id/team`[cite: 22].
3. **Slice 102c (P0 - Services):** `GET /v1/me/services`, `POST /v1/services`,
   `POST /v1/studios/:id/services`, `PATCH /v1/services/:id`, `DELETE /v1/services/:id`[cite: 22].
4. **Slice 102d (P0 - Portfolios & images):** `GET /v1/me/portfolios`, `GET /v1/portfolios`,
   `GET /v1/portfolios/:id`, `POST /v1/portfolios`, `POST /v1/studios/:id/portfolios`,
   `PATCH /v1/portfolios/:id`, `DELETE /v1/portfolios/:id`, `POST /v1/portfolios/:id/images`,
   `PATCH /v1/portfolio-images/:id/tags`[cite: 22].
5. **Slice 102e (P1 - Invitations, members, resources & add-ons):**
   `GET /v1/me/invitations`, `POST /v1/studios/:id/invitations`, `PATCH /v1/invitations/:id`,
   `PATCH /v1/studios/:id/members/:userId`, `DELETE /v1/studios/:id/members/:userId`,
   `GET /v1/studios/:id/resources`, `POST /v1/studios/:id/resources`,
   `PATCH /v1/resources/:id`, `DELETE /v1/resources/:id`,
   `GET /v1/services/:id/add-ons`, `POST /v1/services/:id/add-ons`[cite: 22].

Out of scope: `POST /v1/portfolio-images/:id/index` (owned by BE-104),
`GET /v1/studios/:id/dashboard` (allocated to P2 / BE-108), uploads and projects (BE-103),
bookings (BE-105)[cite: 22].

## Dependencies and open decisions

- Builds on BE-101 (`defineRoute`, `PgDatabase`/`Transaction`, `authenticateVerified`,
  `ApiError`). Stacked on `feature/BE-101-api-contract-auth` and retargeted to `dev` once
  BE-101 merges[cite: 22].
- Temporary catalog query/response/input schemas live in `apps/api/src/schemas/catalog.ts`
  until Khoa's shared handoff merges into `packages/shared`[cite: 22].
- DB-102 migrations and `public.providers` view from Ly are required before Cloud verification[cite: 22].
- Manager authorization is checked against `studio_members` (`role = 'manager'` and
  `studios.deleted_at IS NULL`) inside the request transaction[cite: 22].

## Acceptance criteria

- [x] Static `/v1/photographers/me` is registered before `/v1/photographers/:id` and both are tested[cite: 22].
- [x] Public reads exclude hidden/deleted providers, draft portfolios, hidden images and inactive services[cite: 22].
- [x] `GET /v1/explore` supports `genre`, `city`, `district`, `priceMax`, `page` and `pageSize <= 50`[cite: 22].
- [x] Studio creation atomically inserts the studio and its first `manager` in `studio_members`.
- [ ] Services and portfolios enforce a single owner (personal photographer or studio) and soft deletion[cite: 22].
- [ ] Invitations and membership changes protect the last studio manager and active booking assignments[cite: 22].
- [ ] `pnpm check` passes; Cloud checks recorded as Blocked until DB-102 is deployed[cite: 22].
