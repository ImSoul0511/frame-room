# BE-105: Booking, scheduling, brief approval and workspace

Status: In Progress
Owner: Khai
Reviewers: Khoi Nguyen; Ly for DB interaction; Khoa for wire shapes
Jira: None
Branch: `feature/BE-105-booking-scheduling`

## Goal and scope

Implement the booking lifecycle, schedule reservation, brief versioning/approval,
workspace projection, and personal provider schedule endpoints on top of the BE-101
foundation. Target date 2026-11-14 to 2026-11-16 (see the
[work plan](../../docs/backend/mvp-rebuild-work-plan.md)).

In scope, split into five slices on `feature/BE-105-booking-scheduling`:

1. **Slice 105a (P0 - Booking creation & reads):** `GET /v1/bookings`,
   `POST /v1/bookings`, `GET /v1/bookings/:id`, plus shared DB-backed authorization
   helpers in `apps/api/src/services/access.ts`.
2. **Slice 105b (P0 - Lifecycle transitions & rescheduling):**
   `POST /v1/bookings/:id/transitions`, `PATCH /v1/bookings/:id/schedule`.
3. **Slice 105c (P0 - Brief versioning & approval):**
   `POST /v1/bookings/:id/brief-versions`,
   `POST /v1/bookings/:id/brief-versions/:briefId/approve`.
4. **Slice 105d (P0 - Workspace projection):** `GET /v1/bookings/:id/workspace`.
5. **Slice 105e (P1 - Personal & resource schedule blocks):** `GET /v1/me/schedule`,
   `POST /v1/me/schedule/blocks`, `DELETE /v1/me/schedule/blocks/:id`.

Out of scope: `GET /v1/me/timeline` and all shoot-room write operations (messages,
decisions, milestones, gallery uploads/selections, deliveries, reviews), which are
owned by BE-106; media signed URL generation (BE-103).

## Dependencies and open decisions

- Builds on BE-101 (`defineRoute`, `PgDatabase`/`Transaction`, `authenticateVerified`,
  `ApiError`). Stacked on `feature/BE-101-api-contract-auth` and retargeted to `dev` once
  BE-101 merges.
- Temporary booking/schedule/brief/workspace schemas live in
  `apps/api/src/schemas/bookings.ts` until Khoa's shared handoff merges into
  `packages/shared`.
- DB-102 migrations (`public.frameroom_transition`, `public.frameroom_reschedule`,
  `private.*` helpers, and `schedule_entries` GiST exclusion constraints) from Ly are
  required before Cloud verification.
- Booking state transitions and slot/resource reservations are delegated exclusively to
  `public.frameroom_transition` and `public.frameroom_reschedule` inside the request
  transaction; TypeScript does not duplicate transition or overlap logic.
- Workspace media entries (`messages`, `images`, `deliveries`) return `url: null`
  alongside `storagePath` until BE-103 (`MediaService`) merges.

## Acceptance criteria

- [x] `POST /v1/bookings` enforces project ownership (403), single booking per project
      (409 `project_already_booked`), active/visible service (404), non-self provider
      (422 `self_booking`), active service add-ons (422 `invalid_add_on`), and `<= 24h`
      interval (422 `invalid_interval`), snapshots service + add-ons, and increments
      `creative_projects.version`.
- [x] `GET /v1/bookings` returns up to 100 bookings readable via `private.can_read_booking`,
      and `GET /v1/bookings/:id` returns 404 for non-participants.
- [x] `POST /v1/bookings/:id/transitions` (200) and `PATCH /v1/bookings/:id/schedule`
      (200) call DB RPCs with positional arguments and map SQLSTATE errors (`40001` ->
      409 `stale_version`, `23P01` -> 409 `slot_overlap`, `23514` -> 422, `42501` -> 403,
      `P0002` -> 404).
- [ ] Brief versioning increments sequentially, auto-approves the author's side, blocks
      locked bookings (422 `brief_locked`) and superseded versions (409 `stale_brief`),
      and updates `agreed_brief_version` once both sides approve.
- [ ] `GET /v1/bookings/:id/workspace` returns the 13-part workspace projection with
      participant access control and visibility gating (draft galleries provider-only;
      deliveries hidden from clients until `delivered`/`completed`).
- [ ] `GET /v1/me/schedule`, `POST /v1/me/schedule/blocks` (201), and
      `DELETE /v1/me/schedule/blocks/:id` (204 empty body; 422 `booking_reservation` if
      attached to a booking) work for owned photographers and managed studio resources.
- [ ] `pnpm check` passes; Cloud checks recorded as Blocked until DB-102 is deployed.
