# BE-101: API contract, Auth/profile and route registration

Status: In Progress
Owner: Khai
Reviewers: Khoi Nguyen; Khoa for wire shapes
Jira: None
Branch: `feature/BE-101-api-contract-auth`

## Goal and scope

Freeze the API foundation that later backend tasks build on, then implement the identity
endpoints. Target date 2026-11-12 (see the
[work plan](../../docs/backend/mvp-rebuild-work-plan.md)).

In scope, split into two stages:

1. Independent foundation (no shared-schema dependency): validated environment, error
   envelope and mapping, Supabase bearer authentication, transaction-scoped database
   adapter, route-module interface with OpenAPI registration, `GET /v1/config`,
   `GET /v1/openapi.json`.
2. Identity endpoints (waits for Khoa's shared handoff): `GET/POST/PATCH /v1/me` and
   `GET/POST/PATCH /v1/photographers/me`.

Out of scope: catalog, uploads, search, booking, AI, migrations, generated DB types,
`Accept-Language` and `Idempotency-Key` handling.

## Dependencies and open decisions

- Shared schemas (`profileInputSchema`, `photographerInputSchema`, `errorSchema`,
  `idSchema`) come from the MVP `business.ts` through Khoa's handoff, per the
  [frontend manifest](../../docs/transition/frontend-shared-push-manifest.md). Status of
  that PR: not found on `origin` at 2026-11-12. Confirm with Khoa.
- DB-101 identity decision and DB-102 schema are needed before Cloud verification.
- Decision, proposed: keep `POST /v1/me` (201 first create, 200 same-user retry) and a
  read-only `GET /v1/me` (404 `profile_required`), as in the MVP reference. ADR 0003
  proposes `/me/onboarding`. To confirm with Ly and Khoa, then update the ADR.
- Decision (Khai, 2026-11-13): no `.strict()`. The MVP `business.ts` uses none (38
  `z.object` schemas, Zod default), so unknown body keys are ignored. Identity and roles
  never come from the body, and responses are re-parsed through their schema. Revisit
  only if Khoa asks for rejection.
- Decision pending: 502 versus 503 for model failures. Mapping here uses 503.
- Dependencies added to `apps/api`: `pg`, `@types/pg`, `@supabase/supabase-js`,
  `zod-to-json-schema`. The lockfile change must be coordinated with other PRs.

## Acceptance criteria

- [ ] `GET /health` response is unchanged.
- [ ] Every business error uses `{error:{code,message,details:[]}}` with stable reasons.
- [ ] Missing, invalid or expired bearer token returns 401; unverified email returns 403.
- [ ] Actor identity comes only from the verified token, never from body or metadata.
- [ ] Database actor claims are transaction-local and cleared when connections return.
- [ ] `GET /v1/config` and `GET /v1/openapi.json` are public and expose no secrets.
- [ ] A module registers its routes and OpenAPI entries through one small interface.
- [ ] Stage 2: `/v1/me` and `/v1/photographers/me` behave as in the work plan section 4.
- [ ] `pnpm check` passes; Cloud checks recorded as Blocked until DB-102.

## Contract impacts

- API: new public `GET /v1/config` and `GET /v1/openapi.json`; stage 2 adds the six
  identity routes.
- Shared: none from this task until Khoa's handoff merges; later changes need Khoa's review.
- ERD, migrations, DB types: none.
