# UI-001: Editorial discovery and connected authentication

Status: In Review

## Scope and decisions

Implement the user's second visual reference in the existing application: cream
paper, lavender framing, blue typography and botanical accents. Move navigation to
the upper left. Keep idea/image search in its own section and reserve the upper
right search for names. Use Lora and Be Vietnam Pro with Vietnamese glyph support,
clear contrast, concise bilingual copy and no new application logging.

Read the supplied architecture and use-case DOCX files for discovery, account,
portfolio and role context. Those files are reference material; the user's explicit
screen requirements take priority. Preserve the existing client/photographer public
registration model and metadata-as-preference boundary.

The user explicitly selected **keep no-public-images placeholders**. Do not inspect
or publish private/draft portfolio content. The automatic approval review rejected
a broader privileged metadata inspection; implementation continued through public
queries, without that inspection.

## Implementation

- Horizontal navigation, separate username search and dedicated idea-search panel.
- Responsive editorial layout, botanical SVG accents and accessible named controls.
- Real provider cards, taxonomy-based genre filters, city/budget filters and sorting
  by name, price or rating. Missing prices and ratings are not fabricated.
- Shared light color mode prevents dark-mode text/background mismatches.
- Supabase signup/login/confirmation/recovery and resumable onboarding.
- Cloud REST adapter for the requested account/catalog subset when no SQL connection
  is configured. Existing SQL behavior remains selected when configured.
- Correct nullable taxonomy labels and one-to-one photographer search results.

Configuration and supported scope are documented in the
[Cloud preview guide](../../docs/infrastructure/supabase-cloud-preview.md).
No migrations, database content changes, publication, commits or pushes were made.
Existing staged and unstaged work was preserved. Fetching Git refs was unavailable
because `.git/FETCH_HEAD` was read-only; refs were not claimed current.

## Verification

- Public Cloud/API reads: 24 providers and 146 active taxonomy tags; provider detail
  and public name-search requests returned HTTP 200. Public covers were null.
- Supabase public Auth settings: email enabled, registration enabled, email
  confirmation required. An invalid-credentials request returned HTTP 400 with
  `invalid_credentials`; unauthenticated own-profile access returned HTTP 401.
- TypeScript compilation passed for shared, API and web.
- Production Vite build passed, with the existing large-entry-chunk warning.
- All 195 tests across 22 files passed. New cases cover scoped account
  writes, unverified-account rejection, retry/race recovery, nullable tags, safe
  return URLs and one-to-one public profile relations.
- Changed TypeScript files passed ESLint and formatting checks.
- Documentation link/translation checks and `git diff --check` passed.
- A local scan of the production web output found no configured private credentials.

The installed runtime is Node 24.11.1; the repository pins Node 22.13–22.x. Checks
were invoked directly through the installed Node/TypeScript/Vitest/Vite entrypoints
because the normal pnpm lifecycle enforces the pinned engine. Repeat standard
`pnpm check` under Node 22 before merging.

Browser visual/keyboard checks at 375px/1280px were **not run**: the browser tool
reported no available browsers, and both IAB and Chrome entrypoints were unavailable.
Responsive rules were implemented, but rendered layout is not claimed verified.
Successful signup, mailbox confirmation, recovery email delivery and authenticated
Cloud writes were **not live-tested**. No email or Auth account was created by the
verification. Complete those checks using a user-controlled account and confirm the
Supabase callback allowlist. Privileged account-write behavior was tested with
mocked Cloud responses, not the live privileged credential.
