# RLS policies and grants

Source: MVP branch `supabase/migrations/20261030000100_mvp_core.sql` and `20261030000200_mvp_workflows.sql`. All application public tables have RLS enabled. The initial migration creates SELECT policies named `<table>_read`; business writes are performed by the authorized API using server credentials, while anonymous/authenticated grants are read only. Recreate grants and function execution restrictions as carefully as policies.

| Policy family           | Confirmed read rule                                                                                                                                                                                                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public identity/catalog | `profiles_read` permits profile row read; `photographers_read`, `studios_read`, `services_read`, `portfolios_read`, `images_read`, `reviews_read` restrict hidden/draft/deleted state with owner/admin exceptions; `tags_read` is public. Avoid exposing private profile fields through public projections. |
| Own/member              | `roles_read` own only; `members_read` own or manager; `invitations_read` manager or recipient; `resources_read` manager.                                                                                                                                                                                    |
| Booking/project         | `projects_read`, `bookings_read`, `schedule_read`, `snapshots_read`, `briefs_read`, `rooms_read`, `messages_read`, `decisions_read`, `milestones_read`, `galleries_read`, `gallery_images_read`, `selections_read`, `deliveries_read` use private access helpers and state checks.                          |
| AI/report               | `reports_read` reporter/admin; `ai_messages_read`, `artifacts_read` project access; `ai_jobs_read` own job plus project access; `usage_read` own/admin; `actions_read` proposed recipient plus project access.                                                                                              |

Helper functions `private.is_admin`, `is_manager`, `owns_provider`, `provider_visible`, `provider_side`, `can_read_booking`, `can_read_project`, `can_read_room`, `can_read_gallery` are `SECURITY DEFINER` with fixed search path to avoid recursive RLS. Privileged booking, queue and budget RPCs are revoked from `public`, `anon`, `authenticated` and granted to `service_role` in migration 2. `storage.objects` has `private_media_read` and `owned_media_insert` policies; see [storage configuration](storage-configuration.md).

Reconstruction acceptance: test each actor in [authorization matrix](../backend/authorization-matrix.md) with two real accounts and current/removed memberships. Test both API denial and direct Supabase read denial; service-role tests alone cannot prove RLS.
