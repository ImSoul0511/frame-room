# Service specifications

Source: MVP branch `apps/api/src/services/`, `repositories/database.ts`, `routes/business.ts`, and `worker.ts`. These are implementation references for a rebuild, not code on checked out `main`.

| Service                                    | Responsibility and transaction boundary                                                                                                              | Failure/invariant                                                                                                                          |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `providers.ts`, `access.ts`                | Resolve verified profile, provider ownership, studio manager, booking/project participants. Create profile/photographer/studio plus initial manager. | No client-supplied grant; current membership controls authority.                                                                           |
| `catalog.ts`                               | Visible provider search, services/add-ons, portfolios/images/tags; publication and soft deletion.                                                    | Hidden/draft content excluded publicly; media path tied to owner.                                                                          |
| `projects.ts`                              | Create/update owned creative project; version brief and attach references.                                                                           | Project version increments; participant cannot write another owner's private project.                                                      |
| `bookings.ts`                              | Snapshot service/price, validate booking transitions, assignment and rescheduling through SQL locks/functions; build workspace.                      | Atomic schedule/resource reservation; stale version 409; no cancellation after proofing; agreed brief replacement requires both approvals. |
| `collaboration.ts`                         | Room messages, decisions, milestones, gallery rounds, deliveries and reviews.                                                                        | Only current participants; no premature media disclosure; lifetime unique review.                                                          |
| `media.ts`                                 | Validate multipart bytes with Sharp, normalize previews/thumbnails, enforce Storage path ownership, issue five-minute signed URLs.                   | Reject unsupported MIME, oversize and remote URL injection; issued URLs remain valid until expiry.                                         |
| `ai.ts`, `search.ts`                       | Gateway generation/embedding, parse bilingual search, rank matching published images and providers; reserve/settle usage.                            | 768-vector model compatibility; no paid retry after unknown outcome; missing key is unavailable.                                           |
| `ai-jobs.ts`, `ai-actions.ts`, `worker.ts` | Idempotent enqueue/claim/archive, access recheck, concept/edit/cull/index processing and explicit action confirmation.                               | Job redelivery cannot duplicate artifacts; uncertain state retains reservation; action expiry/version rechecked.                           |
| `maintenance.ts`                           | Expire/clean references and operational data in worker.                                                                                              | Only scoped cleanup; preserve durable booking history.                                                                                     |

The API must own business writes and explicit authorization even when using a service-role database connection. Do not rely on RLS bypass as permission. SQL RPCs and constraints provide a second consistency boundary. Require tests with two unrelated accounts, current and removed members, conflicting schedules, stale versions and repeated idempotency keys.
