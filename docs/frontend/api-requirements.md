# Frontend to backend requirements

The route list in [backend endpoint inventory](../backend/endpoint-inventory.md) records the complete MVP implementation surface. This table groups required responses by visible workflow. Use the MVP branch `apps/web/src/lib/types.ts`, `packages/shared/src/business.ts` and page components to finalize field names; the older `docs/api/contract_v0.md` is not implementation truth.

| Workflow            | Reads and mutations                                                                       | Required response behavior                                                                                                    | Blocking dependency                    |
| ------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Session/onboarding  | `/v1/config`, `/v1/me`, `/v1/photographers/me`; POST/PATCH own profile                    | `{data}`; 404 `profile_required`, idempotent same-user POST `/me`, server-derived roles                                       | Auth verification and unique username  |
| Discover            | `/v1/explore`, `/v1/photographers`, `/v1/studios`, details, `/v1/tags`, `POST /v1/search` | Filtered provider cards; search-specific parsed query, effective filters, metadata and explanations; no private provider rows | Catalog visibility, embedding index    |
| Project             | CRUD `/v1/creative-projects`, references/artifacts/messages/actions, assistant/chat/jobs  | Owner-scoped project and version, async job status, streaming chat, action proposal vs applied state                          | Project tables, queue, AI service      |
| Booking             | `/v1/bookings`, workspace; transitions, schedule, brief versions/approve                  | Current state/version and complete authorized workspace; conflict on stale version; no premature delivery/gallery exposure    | State machine and schedule constraints |
| Room/proofing       | Room messages/decisions/milestones, gallery images/selections/reopen, deliveries/reviews  | Chronological room state, signed private media, selection round and unique review                                             | Storage RLS and booking authority      |
| Provider management | Studio/team/invitation/resources/dashboard, services/add-ons, portfolios/images/tags      | Owner or current manager projection; public draft exclusion; soft deletion                                                    | Membership and catalog tables          |
| Settings/admin      | Own schedule/timeline/usage, reports, admin reports/moderation                            | Account-scoped metrics; admin-only moderation                                                                                 | Usage ledger and role provisioning     |

Common protocol: `GET`/`PATCH` use 200, most `POST` use 201, AI job submission 202, deletion 204 where specified in `apps/api/src/routes/business.ts`; health remains unenveloped. Errors are `{error:{code,message,details:[{reason}]}}` (MVP `docs/api/mvp.md`). Path IDs are UUIDs; page and filter query parameters require explicit validation. The rebuilding team must decide whether to retain the MVP's exact wire format or version changes before the UI handoff. No password is sent to Fastify.
